# FB Skill 源码驱动重做

## 需求与授权

用户在本会话明确要求：可推翻原有实现、全新安装、清除旧 FB rules，不背兼容包袱；并在最近真实消息中要求“继续”。这授权本次 Skill 产品实现与隔离测试，不授权远端发布、git commit/push、真实数据库修改或无差别删除工具/业务目录。

该轮历史记录中没有采集并确认用户显示名。Git/OS 只作为候选，**本档案不伪造一位批准人，也不宣称已通过新版的实名方案批准机制**。该轮对具体产品能力的继续授权来自实际会话；模拟审批仅用于临时回归，不写真实 workflow。后续以有效项目/全局身份档案为准，直接复用，不根据本段历史状态反复询问显示名。

## 方案与范围

见 [设计](../design.md)：三个短 Skill 入口，按实际项目/版本/组件拥有者取证，身份候选与确认、方案版本/哈希、追加审计、归档，干净安装和精确旧文件清理。

修改集中在 fb-skill。参考业务代码只读；此前误写的真实全局 profile 查看后失效化，旧演练的合成审批明确纠正。

## 文件/API

- `skills/create-fb-feature/`：按需路由与各端小参考；detect、identity、workflow、archive。
- `skills/use-fbjs-vue2/`：kebab 本地覆盖、hoisted 包、owner/file 收窄与版本隔离。
- `skills/manage-fb-skill/`：scan/plan/apply 安装与精确指纹清理，不调用旧CLI。
- `bin/fb-skill.cjs`、`package.json`、CI/check/tests：可分发/可回归结构。
- README、需求指南、证据/调研、问题台账、CHANGELOG、验证报告。

## 留痕纠正

旧演练中“同意”、显示名和13:05—13:16时间线并非真实输入/时间。本轮明确停用，不补造批准。本机脚本真实采集的日志带时区；产品的权限范围与宿主消息真实性边界有说明。
