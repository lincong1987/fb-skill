# 开发人员需求指南

**不必先学框架。** 告诉 AI 做什么、给什么参考、有什么业务限制；目录、组件和现有接口等能在项目里查到的内容由 AI 自己查。

## 30 秒写法

```text
在设备模块增加报废列表和提交弹窗。
参考图1（列表）、图2（表单），沿用项目风格。
查询：名称、状态。表单必填日期和说明。
保存成功刷新列表，取消不刷新；权限沿用模块现状。
接口文档在 docs/api/device.md；缺的接口请先列在方案里，不编造已就绪接口。
```

这是虚构示例，不是你必须采用的业务字段、权限码或 URL。只有一张图、一个小改也可以使用 Skill。

## 一句话小改

```text
给当前设备列表加“最近维保时间”一列，接口已返回 lastMaintainTime。
先找到当前页面和接口定义，沿用原来日期显示方式，不改其他业务。
```

AI 应定位并提出修改范围，而不是让你把所有字段/权限/目录重新填一遍。

## 原型怎么给

| 材料 | 怎么提交 |
|---|---|
| 单张图片 | 粘贴 png/jpg，或提供 AI 可访问的本地文件路径；标明做整页还是其中一个区域 |
| 多图 | 标注图1列表、图2新增、图3详情，以及哪些是不同状态；弹窗单独截图 |
| 图片 + 文字 | 图片说明布局，文字补校验、权限、点击后动作、空/错/加载状态 |
| 原型 URL | 给实际可访问 URL 和目标页面；需要登录时走已授权会话，不上传私有设计给陌生服务 |
| 项目参照 | 指定一个已实现页面；可以写“参考布局，不抄接口/业务” |

看不清、打不开、未提供的部分 AI 会明示，不会装作已经读取。清晰整页图能减少来回，图上英文 API 名不是必要输入。

## 完整功能模板（按需填，不必全填）

```markdown
功能：
本次范围：PC / App / 大屏 / Java / SQL 中哪些，哪些不改：
参考：图片/链接/已有页面：
操作：查询、新增、编辑、详情、删除、导入导出等：
业务限制：必填、长度、唯一性、状态流转、权限/记录归属：
数据来源：已有接口/模型/表/字典在哪里；未就绪部分：
验收：具体要看到或操作成功的结果：
```

有接口/字段文档时附上。只有中文字段也可以，AI 先查已有映射；找不到则提出映射让人确认，而不是把虚构英文字段直接接后台。

可选字段表：

| 字段/中文名 | 用途 | 校验/取值 | 列表 | 查询 | 数据来源/备注 |
|---|---|---|---|---|---|
| 名称 | 输入 | 必填，最多100字 | 是 | 模糊 | 后端字段待核对 |
| 状态 | 选择/显示 | 现有状态字典 | 是 | 是 | 字典位置已知则给路径 |
| 日期 | 日期 | 仅日期/时间点 | 是 | 范围 | 展示和提交格式由目标接口核实 |

## 三个场景

**移动端**

```text
在当前 App 增加设备报废列表和提交页，沿用已有页面壳/组件。
按设备名称搜索，点击进入可直达详情，提交成功只刷新一次再返回。
请先确认这是 TA-UI 还是旧 TX 项目；不要因为都是移动端就混组件。
```

**大屏**

```text
按图1做统计大屏，图2是企业详情弹窗。
图按1920×1080设计，但在16:10上也应保持比例；不要拉伸文字。
主题沿用本入口，30秒刷新数据，切页后停止轮询。
接口未就绪，先做明确标注的 mock 演练并列联调待办。
```

**后端/SQL**

```text
为这个功能新增接口与表，跟随当前 Java 模块与 MySQL/达梦适配方式。
管理员可查全部，其他人只能操作自己的记录。
先核对真实平台响应、主键、审计与删除方式，不重新生成平台 BaseEntity。
提交 SQL 文件，不直接连接或修改真实数据库。
```

## 用户批准与留痕

1. AI 先查工程和本次 API，只加载相关参考。
2. 输出可审方案：字段/交互、文件、接口、权限、验证、缺口。
3. 真实人批准**当前版本**后才实施。提出改动则修订再批准；“继续调查”和另一方案的批准不替代这一步。
4. 实施与验证实时留痕，经归档命令预览、确认写入后产出 `CHANGELOG.md` 和 `docs/features/<任务id>.md`。

**留痕显示名只登记一次，不是每个需求都填写。** AI 先读已保存档案：有有效记录就直接用，不再问姓名，也不重新保存。没有记录时自动取 Git/SVN/系统候选，首次确认或补充一次即可；候选不能冒充批准人。邮箱可选，默认项目保存；经你授权保存为全局档案后，可跨工程复用。身份复用与批准当前开发方案是两回事。

测试身份、模拟“同意”、沉默和普通工具通知不能作为真实批准。宿主有真实计划批准结果时，可保留该界面来源与已展示方案，不能由AI补一条聊天“同意”；已展示并获批的日志标签可一次保存，但不冒充实名认证。时间由脚本采集，方案修订号/hash 与批准一起记录；本地审计不是企业账号或数字签名认证。

## 怎么看交付

AI 应说明：**实际改了什么、哪种验证做了、哪些没做或失败**。静态 parser/guard 通过不等于浏览器、真机、接口联调、Java 编译或 SQL 已执行。

接口未就绪、权限/字典待配置、平台依赖缺失会明确列待办；不会通过假成功 toast 把功能冒充完成。参考项目的手写问题独立记账，本次不会无关整改。
