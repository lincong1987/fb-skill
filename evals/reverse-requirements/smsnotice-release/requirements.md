# 公告管理对照试点需求 · 本轮已批准

案例：smsnotice-pilot。用途：从已有页面反推候选需求，测试按需求重做的保真度；不是线上业务开发。

本轮宿主计划明确确认以下试点规则与生成范围；仍仅为本地mock演练。接口、字典、字段编码和环境版本见配套 contracts.json；这些技术细节不要求开发人员口述。

## R01 范围与运行边界

在当前 PC 管理后台框架中做一组公告管理页面，包括列表、弹窗新增、草稿编辑、已发布公告只读查看、单条删除。

第一轮只用合成用户、字典、公告和本地 mock 接口。页面明确显示“MOCK 对照试点，非真实接口”；不连接真实后端、不修改数据库，不向外部上传文件。

## R02 查询条件

查询区包含公告标题、公告类型、发布日期起止和状态。类型、状态是下拉选择；发布日期以年月日显示，开始日期不能晚于结束日期，空日期不限制查询。

进入页面自动加载一次列表。点击查询按当前条件加载，并回到第一页。点击重置清空全部查询条件，回到第一页并查询一次。（本轮已确认。）

## R03 列表与按钮位置

按本项目标准列表布局：查询条件在上方；条件区下方、表格上方的工具栏左侧是“发布公告”，右侧是“查询”“重置”。相邻按钮有间隔，不依靠文本空格撑开。

列表列为公告标题、发布单位、公告类型、发布日期、状态、操作，支持分页。标题可点击打开阅读详情；草稿行提供“修改”，已发布行提供“查看”；两种状态的行都可以显示“删除”，但各入口受对应操作权限控制。

本轮只做单条删除，不扩展撤回、批量删除或个人中心页面。已发布行能否删除为试点建议，本轮已确认。

## R04 新增与编辑字段

“发布公告”打开新增弹窗，草稿的“修改”打开编辑弹窗。字段包括公告标题、公告类型、发布日期、发布单位、公告范围、附件和公告正文。

新增日期默认本地 mock 时钟的今天；编辑时保留原日期，日期只读。新增发布单位取合成当前用户所在单位，编辑时回显原发布单位，单位只读。公告范围可多选；编辑应回填全部原内容，空范围或缺失范围显示为空选择，不崩溃。

正文支持富文本编辑；附件范围见 R10。编辑保留原日期是试点建议，本轮已确认。

## R05 草稿与发布

编辑弹窗提供“暂存为草稿”“保存并发布”“取消”。保存草稿仍是草稿；保存并发布成功后成为已发布公告。

试点建议：草稿只要求标题非空，允许类型、范围、正文、附件尚未完成；发布要求标题、类型、发布单位和公告范围必填，正文和附件本轮不强制必填。校验未通过时提示对应字段，不发保存请求。

草稿最低必填规则本轮已确认，不能把旧代码跳过校验直接当作正式业务制度。

## R06 成功、取消与刷新

保存成功提示并关闭弹窗，父列表只查询刷新一次，保留当前筛选条件并回到第一页。删除成功也只刷新一次。

取消新增或编辑、关闭只读详情都不发保存请求，也不刷新列表。以上刷新规则为试点建议，本轮已确认；它不要求修改旧业务工程。

## R07 两条只读查看入口

保留两个入口的区别，不擅自合并：

- 点击公告标题打开阅读详情，展示标题、发布单位、发布日期、附件和正文，底部只有“关闭”。
- 已发布行的“查看”打开只读表单，展示新增/编辑表单的字段，但不显示草稿或发布保存按钮，所有字段不可修改。

以详情返回的实际状态为准：如果打开时公告已经发布，不允许从过时的草稿行进入编辑后再保存。状态变更时保守转为只读是试点建议，本轮已确认。

## R08 删除与权限

新增、修改、查看、删除按各自权限显示入口。没有相应权限时不能仅靠直接调用页面处理函数发起写请求；这是本轮前端防误操作检查，不冒充后端鉴权。

删除前提示确认。取消确认不发删除请求、不刷新；确认后只删除该公告。成功提示并刷新，失败显示错误，保留列表数据。本轮支持草稿和已发布两种状态的单条删除，本轮已确认。

## R09 失败、重试与重复点击

保存中按钮显示等待并防止重复提交。保存返回失败或请求异常时，弹窗保持打开，标题、类型、范围、正文和附件输入保留，解除等待后可以重试；不能因提交转换破坏表单值。

保存并发布失败时不把本地草稿冒充已发布，列表也不提前改状态或刷新。加载详情失败时提示错误，不让未加载完整的记录进入可保存状态。列表查询失败时提示错误；如果已有列表数据则保留，没有数据则保持空列表，不把失败冒充查询成功。

这些异常处理是试点建议，本轮已确认，不以旧代码缺少防护为标准答案。

## R10 附件与正文的第一轮范围

显示可编辑/只读附件组件，支持 Word（doc/docx）、Excel（xls/xlsx）和 PDF 的本地 mock 记录；保存时把附件记录随公告数据传递，查看时展示已有记录。

正文编辑态可编辑，查看态经过项目内容过滤能力展示，不能直接执行正文里的脚本内容。

本轮不访问真实上传、下载、预览服务，不测试真实文件内容、大小上限、服务端文件权限或富文本复杂编辑；这些项目记录为未执行，不能写成通过。

## R11 数据与验证口径

使用契约附件中的合成数据、可控日期和失败开关，列表、详情和保存结果来自同一组 mock 数据。正常成功、服务失败和请求异常要能分别测试。

验收按字段、布局、状态、请求和异常行为逐项比对，不要求变量名或源码字节与旧页面相同。没有可运行旧页面截图时不声称像素级一对一；mock 通过不代表真实业务联调通过。

## R12 本轮已确认的试点选择

| 编号 | 本版建议 | 需要确认的原因 |
|---|---|---|
| D01 | 查询/重置都回第一页；重置后自动查询 | 旧页只清条件，是否立即查询不是代码事实能决定的 |
| D02 | 新增日期默认今天，编辑保留原日期，两者只读 | 旧实现会把回填日期覆盖成当天，不能照抄 |
| D03 | 草稿只要求标题；发布要求标题、类型、单位、范围 | 草稿可缺字段的最低业务门槛需要明确 |
| D04 | 成功只刷新一次、保留筛选并回第一页；取消、只读关闭不刷新 | 旧页不区分关闭原因，可能产生多余查询 |
| D05 | 保留两条只读入口；详情状态优先；无权限直调也不发写请求 | 不信任陈旧行状态；权限隐藏不等于页面处理函数已防误操作 |
| D06 | 有删除权限时允许两种状态单条删除，不增加撤回/批量 | 发布后的删除策略不是前端按钮存在就证明合理 |
| D07 | 防重复、保存失败可重试、不提前改状态；详情失败禁保存、列表失败保留 | 旧实现数据变形、防重与失败处理缺口不能作为正确性基线 |

以上只确认对照试点的规则，不授权任何线上公告发布或旧项目整改。
