# 验证清单：只检查本次涉及的领域

**何时读**：实施前列验收条件、实施后检查。这里是可观察的检查，不是把历史差异都宣布成禁令。

## 通用

- 批准的是当前方案/项目/文件范围，修订后旧批准不沿用；操作人真实确认，测试数据不冒充。
- 清单里的每个功能都有实际入口/handler/接口或明确待办；不存在未定义变量、缺 import/ref、错路径/主键/数据字段。
- 对空、加载、错误、权限不足、取消和成功分别处理；mock、骨架、静态编译与真实运行分开报告。
- 修改范围内不新增秘密日志、客户端私钥、SQL 输入拼接、未清理监听/资源。旧问题独立记账，不无关整改。
- 命令退出码直接保留，不用管道末端的退出码冒充测试结果。代理报告由实际 diff/产物/命令核实。

## PC（FB Vue 2）

- 实际注册的 owner 已确认，本地 tp-* 覆盖未漏掉；props/events/slots/methods 与源码对应。
- 查询/重置、pk/选择模型、新增/编辑/详情、取消/成功关闭与刷新都闭环。导出方法有真实按钮与下载处理。
- rule/model/prop 一致，校验失败不发请求，重复点击不重复提交，保存失败不关闭。
- fb/tp 日期不混 API，提交/回显格式和后端一致；$confirm 回调/Promise 查实现。
- 路由/service/generator/菜单路径匹配，权限码非占位，前端可见性不替代后端授权。
- 窄守卫结果分类；已存在 wrapper、可用 reload 或合法版本差异不被误报为必改。

## 移动端

- 判断 TA、TX、其他 uni 及 Vue 版本；未装 TA 依赖就标包级 API/构建未验证。
- pages.json/分包/导航目标真实存在，传参编码，详情可直达；保存成功刷新一次，取消不刷新。
- 校验/结果 helper 按目标定义，变量和返回值一致。H5-only 全局不误用于 native。
- 页面/组件生命周期清理；上传认证与附件归属明确；Store 持久路径对应真实模块名。
- TA 项目（[团队规范](frameworks/ta-app-mobile.md)）：`jpx-icon-*` 类名在项目 iconfont CSS 中真实存在，不编造；`txHeight` 由设计稿 `topY`/`bottomGap` 换算并注释取值，不写死经验值。
- 图片/附件用 `ta-image-uploader`/`ta-file-uploader`，新增与详情 `referType` 一致；1.x 版本线不出现 `customResultMapp`、`fileSize`、`@fileExceedLimit`、`lgnoreDelIds`。
- pages.json 注册方式（主包/分包、`navigationStyle`）与目标现有页面一致；修改页可凭 id 直达，不只靠 Store 回显；保存不重复提交。
- 新页面用到的每个 `ta-*` 标签要么在 `componentRegistration.registered`、要么是本地组件或命中 easycom、要么在页面内 import；照抄的参考页不在 `skippedReferenceModules` 里。

## 大屏

- 实际入口/主题/组件 owner 正确；动画包装不冒充布局；设计基准和缩放行为与原型一致。
- 首屏/resize/主题/空数据测试，图表 update 与 dispose 的实际拥有者明确。
- 轮询不重叠，卸载后不继续请求/渲染；地图/播放器/实时连接/监听都有释放路径。

## Java/SQL

- Controller、请求模型、VO/Entity、Service、Mapper/XML 与 DDL 的字段类型/名称闭合，所需 imports/方法全部存在。
- 可信身份、操作权限、记录归属、列表数据范围和写操作校验；失败不能伪报成功。
- 事务遵循目标代理/调用方式，异常与回滚可测；不抄 private 自调用或吞异常。
- 参数绑定与白名单排序，分页不双重 LIMIT，批量空集合/空 ID 有保护，唯一/引用/精度有约束。
- 方言、原生/字符日期、主键、逻辑/物理删除遵循已确认设计，不照抄过度模板。
- 构建/测试不会连生产；SQL 未在真实方言执行时只报告静态/映射检查。

### 接口与鉴权（依赖 topinfo-platform 时逐条核；规范见 [TopInfo 接口口径](frameworks/topinfo-api.md)，现行 2.2.x 工程的实现差异见 [版本差异](frameworks/topinfo-versions.md)）

- 每个接口写清 `perms` / `scope` / `businessKey` 三列，真不需要才写 `—`；不凭角色名推断权限。
- 标 `校验(businessKey)` 的写接口，确认其生成端（列表/详情）已标 `生成` **且** `perms` 覆盖成立，否则前端拿不到票、恒 `-45`。
- `buildPassKey` 是**实例方法**，链式接在 `buildSuccess(...)` 后；VO 显式含 `passKey` 字段，漏了静默失效。
- 写接口（改/删）**不列 `20008`**（归属由 passKey 兜底，失败是 `-45`）；只有读接口越界和新增引用节点越界才列。
- 分页出参写 `records` / `total`，不写 `list`，不自造 `PageResult`。查询 DTO **不放** `tenantId` / `deptId` / `ascnId`。
- 错误码**一码一义**，新增前全局搜索是否已占用；业务码放模块自己的枚举。
- 列表/树越界静默过滤，详情越界报 `20008`；两者同时命中时功能权限码优先。

### 表变更与破坏性操作

- 编码时发现要改表结构：**停下回表设计**，不顺手改 DDL；表变更人工评审后才冻结。
- 级联删除：留**审计摘要**（操作人、目标 ID、各表删除行数），不留全量快照；先关联后主表、同一事务，任一失败整体回滚。
- 不做静默级联：递归影响其他对象时，要么拒绝并提示先清理，要么二次确认后显式执行。
- 单次改动**超过 20 个文件先停下报备**，人评估后再动。
- SQL 执行记录的执行人/日期由人填；AI 不代填、不假装跑过。

## 完成声明

| 声明 | 必要证据 | 不足以支持 |
|---|---|---|
| 语法/模板通过 | 实际工具与退出码 | 看起来合理 |
| API 已确认 | 当前 owner/版本源码定义 | 相邻页面使用过 |
| 运行交互通过 | 可运行环境中具体动作/结果 | parser/guard 通过 |
| 后端编译通过 | 指定模块实际编译输出 | 代码片段/假平台 stub |
| SQL 方言通过 | 目标 DB 执行/解析结果 | 正则查了 CREATE TABLE |
| 用户批准 | 真实输入 + 当前方案绑定 | 沉默、agent 通知、合成表格 |

最终如实记录 pass/fail/skipped 和未验证范围，不把“没有报错”提升为全部验收完成。
