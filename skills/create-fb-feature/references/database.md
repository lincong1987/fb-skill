# 数据库设计与 SQL

**何时读**：新表、加字段、DDL/DML、查询或实体映射变化。选择目标 DB 和真实模型，不复制历史“所有表必含”的公共字段。

## 设计前证据

读取目标 DDL/升级脚本、Entity、Mapper XML、数据库驱动/版本和 ID/审计/删除实现。MySQL 与达梦脚本是不同方言，不能互当已执行证据；数据脚本可能含真实人员/凭据，不复制无关值到文档。

字段设计表至少包含：业务含义、列/Java/接口名、类型/长度/精度、可空/默认、约束、索引、单位/时间语义、读写权限。

- 业务主键、唯一键、外键/引用校验与查询方式共同设计。
- 扩展字段只在目标模型确实要求时加入，不给每张新表无条件塞 extend01~03。
- `actived`、`del_flag`、`log_delete`、有效状态和物理删除不互换。保留/删除语义按实际业务、合规与持久层设计。
- 列命名大小写、映射方式、公共字段按目标 DDL；BaseEntity 是否存在/适配先查，不能凭历史文档要求所有实体继承。

## 类型、ID 与日期

金额采用精确小数，BigDecimal 与 DB decimal/numeric 精度、单位和舍入一致；不能固定任何金额都 DECIMAL(12,2)。状态可为数值/字典字符串/枚举，按已确认语义，不强制所有枚举 Integer。

ASSIGN_ID、ASSIGN_UUID、自增、项目 UUID 工具是真正不同契约。列长度与生成值一致，不把 CHAR(32) 的注释“UUID”当雪花 ID 或实际生成保证。

原生日期（DATE/TIMESTAMP/DATETIME）与历史 CHAR(8/14) 分型处理：看查询、驱动、时区、精度、兼容性。传输字符串不意味着数据库必须用 CHAR。已有 String 日期也不无条件迁移；日期显示/传输/存储分别记录。

历史 T750x 类型编号仅在找到目标实际类型表/字典定义时采用，未找到权威定义就不造编号。主键、审计/逻辑字段由已证实机制填，不假设自动 handler。

## SQL 与迁移

- 用参数绑定处理值；动态列/表/排序按服务器白名单。查询列/别名与 result mapping 明确，不把合法固定表达式当注入。
- 分页与插件/数据库版本匹配，避免双重 LIMIT。空 IN、空主键、批量操作边界有保护。
- 索引依据实际过滤、关联、排序及选择性，不给所有 name 字段机械加索引。唯一/引用在数据库或可信业务层有明确保障。
- 变更写可追查迁移，考虑旧数据可空/default/回填、索引创建成本、回滚与锁；不先跑 DROP 或连接真实数据库试错。
- MySQL 注释、达梦 COMMENT ON、方言函数和大小写/模式名分别生成/验证，勿通过替换 VARCHAR 就宣称支持多 DB。

## 验证

优先目标 DB 的隔离实例/实际驱动或批准的测试库；执行 SQL 前单独确认环境和动作。静态检查、XML 解析、实体映射审查与真实执行分别报告。

检查 DDL ↔ Entity ↔ DTO/VO ↔ Mapper/XML ↔ 接口字段闭环，日期/金额/主键边界、分页和权限。没有目标 DB 则标“未执行/方言未验证”，不伪报迁移成功。
