# 需求与原型引导

**何时读**：需求不够具体、包含原型图片/链接，或多页面对应关系不明。开发人员可用简短自然语言，不需要先学习框架 API。

## 最小输入

```text
做什么：在设备模块加报废列表和提交弹窗。
操作与约束：按名称/状态查询；必填日期和说明；保存成功刷新，取消不刷新。
参考：图1列表、图2表单；沿用项目相邻页面风格。
数据：接口已就绪，文档在……；或接口未就绪，先做明确标注的 mock 演练。
```

不把示例表名、字段或 URL 当用户真实业务需求。目标工程可从当前工作区定位；接口/字典/权限码能查就查，不要求用户重复填。

## 读取原型

1. 图片分配可引用的标识（图1、图2或文件路径），列明页面、弹窗与状态对应。
2. 从图读布局、字段、操作、层级；仅文字说明业务校验、数据来源、权限、空/错/加载状态。
3. 使用可用的浏览器或图像能力读取用户给的材料。私有链接不绕认证、不上传到陌生外部服务；打不开如实写明，继续做可以确定的部分。
4. 图与文字冲突时只问关键冲突。模糊小字标未知，不能编字段、请求或成功消息。

## 方案中需要什么

| 范围 | 要点 |
|---|---|
| 小改 | 修改文件、行为差异、验证办法 |
| CRUD | 列表/表单字段、操作、路由/弹窗关系、接口映射、必填/唯一性/权限、失败/取消/刷新 |
| 大屏 | 设计尺寸与布局、缩放行为、主题、图表/地图/视频、数据刷新、异常与清理 |
| 移动端 | 当前 uni/TA/TX 体系、页面/分包、导航传参、刷新返回、上传与原生能力 |
| Java/SQL | 目标模块/方言、字段与约束、身份/权限、事务、迁移、验证 |

没有接口时，区分 **设计契约** 与 **已实现契约**。mock 不写成线上成功；后端骨架、待配置权限或字典如实列待办。

只问真正改变下一步的业务决定，采用显而易见的项目默认即可。长期指南见发布包 `docs/requirement-guide.md`；独立 Skill 安装不依赖该外部文档才能执行。
