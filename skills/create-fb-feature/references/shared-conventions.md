# 跨层契约

**何时读**：需求涉及字段、接口、日期、分页或权限。它们由实际工程决定，不由一份历史模板决定。

## 取证表

实现方案只列本次用到的项目：

| 契约 | 首要证据 | 需要确认 |
|---|---|---|
| 字段/主键 | 后端请求模型、Entity/VO、DDL、已存在接口样例 | 名称、类型、长度、可空、字段权限 |
| 响应/失败 | Controller 返回类型 + 实际拦截器 | 成功码、解包位置、错误是否 reject/返回 undefined、谁负责提示 |
| 分页 | 表格 reader、service 参数、后端分页对象 | current/size 或其他字段、一页下标、records/total、排序 |
| 日期 | 控件输出、DTO/序列化、数据库字段 | 展示/传输/存储分别是什么、时区、仅日期还是时间点、范围端点 |
| 权限 | 指令/菜单服务 + 后端鉴权/数据范围 | 按钮码、操作权限、记录归属、后端强制检查 |
| 下载/上传 | 工程已有服务、文件模型、附件归属 | 认证、响应流、失败解析、大小/类型、回收与业务绑定 |

记录来源为 `文件:行号` 与版本。相邻页面用于发现调用方式，但必须核对定义；可用实际响应不能代替安全检查。

## 响应与分页

已观察的 FB 样本常用 `{ code, message, data, expand }`，`code === 1` 为成功，分页数据常见 `records/total/current/size/pages`。这是**样本契约**，不是任意项目的统一响应。

读取拦截器后再写页面判断：业务失败可能返回 `undefined`、reject 或返回信封；页面应判空，避免重复提示。HTTP 成功不等于业务成功；文件流不硬包 JSON。空数组、网络失败和权限失败都有实际分支。

传输层保持项目约定，字段变化同时检查前端 service、后端入参、Mapper/XML 和测试；不要只改一侧。

## 日期与数值

- 有些历史工程用 `yyyyMMddHHmmss`/`yyyyMMdd` 字符串，有些表有 DATE/TIMESTAMP/DATETIME。选择与目标契约一致的类型；新设计按查询、时区、精度与驱动能力决定，不禁止数据库原生日期类型。
- PC `tp-datepicker` 的 `format` 与 `value-format` 分别控制显示/值；具体格式必须查目标源码。已得到格式化字符串时不再无条件转 Date。
- `dayjs(value, format)` 的自定义格式解析需实际插件支持，不能认为任何 dayjs 实例都能解析 14 位字符串。
- 金额用精确小数类型，约定币种/单位/scale/舍入；页面展示转换不改变接口存储单位。标识、电话号码、字典码不可因为“全数字”就转 Number。

## 权限与安全

前端权限只管可见/可操作体验，后端仍校验身份、业务权限与数据归属。服务器身份从可信认证上下文获取，不能信任客户端自行提交的 `jwtpid` 等字段。

生成代码不抄私钥、密码、长效 token 或个人证件到客户端/档案/日志；运行时客户端配置也是公开的，不是秘密保险箱。公开公钥与需交付的服务地址不等于秘密，但不能复制与本需求无关的内网配置。外发原型或代码需用户授权。

SQL 参数绑定用于数据值；动态表/列/排序采用服务器白名单。库支持的固定方言表达式不自动判为注入；用户输入拼接不得进入 SQL。

## 工程一致性

沿用实际文件命名、注释密度、目录装配与测试框架。无需为小改动新建一堆空 DTO/Enum 或强行补作者名。已存在的本地包装组件先查注册/拥有者，不以“和库同名”为由自动删除。

同一意义只放一个权威契约；具体端的用法见对应端参考。未知或需整改的旧写法留在独立问题台账，不冒充已裁决制度。
